## Architecture

`TurnManager` is the hub: a phase state machine (`WaitingForDrawChoice` → `WaitingForReplaceChoice` → optionally `WaitingForAbilityTarget` → next turn, or `RoundOver`). Other components are small and driven by it:

- `Deck` – shuffled array of card ids 0–51 (`CardInfo.ts`: id = colour*13 + rank; colours red/blue/green/yellow; red King = id 12 = 0 points). Points (one 0, four each of 1–12, three 13s) come from `pointsOf(id)`; ids flow through `TurnManager.pendingValue`, `DiscardPile`, `Card.setCardId()`. Art index in `CardArtLibrary.faceTextures` = id (red A..K, blue, green, yellow). Compare/score with points, never ids, except for identity (art).
- `DiscardPile` – tracks only the top value; always face-up.
- `PlayerHand` – owns `CardSlot` nodes; deals on `start()`, opening peek (only if `isLocalPlayer`), scoring, `revealAll()`.
- `CardSlot` – references a physical `Card` node (`cardNode`); click goes `canTargetSlot()` → `toggleSlotSelection()`. `setCardNode()` is how rank 9 swaps real nodes; `homeCardNode` is restored each new round.
- `Card` – `Label` shows `points` or `"?"`; `slideTo`/`snapTo` animation, `revealFor` timed peek. All players' cards, the drawn-card display and the discard-pile card are siblings under one `CardPack` node.
- `WorldPos` – `getWorldPosition`/`worldToLocal`; sums parent positions only (ignores scale/rotation).
- `BotPlayer` – polls `TurnManager` in `update()` and acts through timed `scheduleAction` steps (the engine has no event system). It decides from a memory of what it legitimately saw (see design reference Section 7) and uses `mistakeChance` to stay beatable.

### Gotchas that span files

- **Human vs bot entry points:** buttons must be wired to `onDrawPileClicked` / `onDiscardPileClicked` / `onCaboButtonClicked` / `onNextRoundClicked`, which are no-ops during a bot turn where relevant (`isInputLocked()`). The bot calls the raw methods (`drawFromPile`, `takeFromDiscard`, `callCabo`, `toggleSlotSelection`, `confirmSelection`) directly. Do not lock the raw methods or the bot locks itself out.
- **Discard pile click is overloaded:** takes the top discard in `WaitingForDrawChoice`; confirms the selection in `WaitingForReplaceChoice` (0 slots = discard drawn card, always legal with no conditions; 1 = replace; 2+ = same-value swap attempt). `confirmSelection()` returns `false` only for an invalid swap attempt (card not from the draw pile).
- **Same-value swap:** selected slots must match each other (drawn value is irrelevant). A correct guess discards all but one matched card (their slots stay empty for the round, so a hand never drops below 1 card).
- **Abilities** fire only when an ability card drawn from the *draw pile* is discarded with nothing selected. Built: 5 forced draw, 6 swap two slots of another player, 7 peek own, 8 peek another player, 9 blind swap own↔another player. Targets are chosen by clicking another player's slot; never self. Ranks 2/3/4/10/11/12 have no ability.
- **Scoring:** a reward score separate from hand scores (can go negative). CABO caller +20 if strictly lowest, else -20 split among the others (lowest non-callers get a double share); +5 to every lowest hand when the pile empties (a CABO call refused because the pile is nearly empty only shows a message); a CABO result overrides the +5. See design reference Section 13.
- **Visibility:** a card the bot draws from the pile stays hidden; one taken from the discard stays revealed. Ability peeks show on the single shared screen. The single-screen prototype keeps a fixed view with seat 0 at the bottom; per-viewer rotation is online-only (design reference Section 15).

## Engine conventions

- `@property` forms: bare primitive, `@property(Node)`, `@property([Node])`. **`@property([CardSlot])` (arrays of custom components) does not reliably compile**; use `Node` arrays plus `.getComponent()`.
- `Node.position`/`setPosition` are local to the parent; use `WorldPos` for cross-hierarchy math.
- Lifecycle: every `onLoad()` runs before any `start()`; `update(dt)` gets seconds.
- Button clicks are wired only through Inspector Click Handlers (no code API), and the target methods must be `public`.
- Prefab-instance script changes may need saving on the prefab asset, not just the scene. Duplicating nodes in the editor does not remap references or reset value fields; re-verify them.
